# Web 安装与 VPS 部署

## 使用部署面板，不用终端管理

1. 将项目源代码上传到 VPS 面板的应用目录，在面板中导入 `compose.yaml` 并构建启动。`Dockerfile` 内置 Go 程序、Git、SSH 客户端和根证书，容器以非 root 用户运行。不要上传真实笔记作为构建上下文；`.dockerignore` 已排除 `.local`、`data` 和环境文件。
2. Compose 默认将服务发布在主机 `127.0.0.1:8080`。在同一 VPS 的站点面板配置域名和 HTTPS 反向代理，代理目标为这个地址。如果代理也运行在独立容器中，应由面板接入相同容器网络并代理 `obblog:8080`；不要把另一容器的 localhost 当作本应用。证书由部署面板管理。
3. 浏览器打开站点 `/install`，设置并确认管理员密码，再选择知识库来源。编辑、图谱和发布默认可用；Git 仓库自动启用同步，普通目录使用本地保存。HTTP/HTTPS Cookie 自动适配，没有功能启用开关或安装码。
4. 完成后跳转后台登录。以后在后台顶部“系统设置”调整配置，使用“Git 管理”手动同步；重启容器或程序不会再次安装。Compose 的重启策略负责进程重新启动。

源代码本地开发只需 `go run .`，默认本机 `127.0.0.1:8080`，数据目录为 `./data`。独立二进制直接启动亦可，不需要先设置密码环境变量。部署面板的进程管理功能也可托管二进制，启动参数仅需基础设施的 `-data` 和 `-addr`，密码和仓库仍通过浏览器设置。非 Docker 部署需先具备 Git；程序不会从网页请求 root 权限安装系统软件。

## 知识库来源

| 方式 | 行为 |
| --- | --- |
| 克隆 GitHub | 输入 `https://github.com/用户名/仓库.git`，可指定分支；完成安装时克隆到私有数据目录中的新目录，自动配置当前分支 upstream |
| 现有服务器目录 | 用目录浏览器选择真实路径；自动识别当前目录的 `.git`（含 worktree 标记），不使用父目录的仓库。仓库需有初始提交和 upstream；安装不自动拉取 |
| 创建空知识库 | 在私有数据目录中创建新空目录，使用本地保存，可直接新建 Markdown |

现有目录选择器只返回文件夹名称，不返回文件内容。路径指 VPS 文件系统，Docker 中指容器内路径，而非浏览器所在电脑。已有笔记可通过面板挂载到容器的独立位置（如 `/notes`），再在页面选择该位置。编辑和 Git 拉取需要目录可写。

不要选择 `/docs` 之类并不存在的示例路径。项目的 `docs` 是程序文档；已有本机测试库 `.local/obsidian-vault` 只是一个可选择的实际目录，不是自动迁移源。初始化不会主动读取、复制或修改它。

## GitHub 凭据

公开仓库可不填 Token，私有仓库需要具备目标仓库读取权限的 Token；网页编辑后推送还需写入权限。通过网页配置的 Token 仅用于 GitHub HTTPS 远端。SSH URL 不在网页克隆范围内；连接已有 SSH 仓库时仍依赖服务器预先配置的 SSH 环境。

Token 存在私有配置文件中（需要用于后续认证，因此不是单向摘要），不回显、不写 Git remote URL、不作为子进程命令参数。应用通过子进程环境注入仅匹配 GitHub HTTPS 的认证头。不要公开数据卷、配置文件、部署日志或备份。修改 Token 时填写新值；留空保留原值，也可明确勾选清除。切换到另一仓库需重新填写或明确清除旧 Token，避免凭据被默默沿用。创建空知识库会清除旧凭据。

首次克隆只下载，不向 GitHub 上传内容。目标仓库需有初始提交；当前不从网页创建 GitHub 仓库、创建远端首个提交或配置分支保护。安装后不定时拉取，仍由后台手动触发。

## 配置与恢复

`data/config.json` 保存版本、目录、自动识别的模式、密码摘要以及可选 Git 凭据，权限为 `0600`。旧读写和 Git 字段保留兼容，但关闭标记不再限制后台功能。管理员密码使用随机盐和 PBKDF2-SHA256（600000 次）保存，没有明文密码。配置采用临时文件同步后原子替换；首次保存为排他创建，另有 `setup.lock` 防止并发初始化。未安装时可直接访问向导和目录选择器；安装完成后初始化 API 返回 410。不再生成或读取安装码文件。

系统设置保存后立即切换配置，所有旧会话撤销，需重新登录；旧笔记目录始终保留，不自动删除。密码留空保留旧密码。更换知识库前请先保存编辑器草稿；原页面入口有未保存提示，但不要同时用多个标签页修改设置和编辑笔记。

首次安装保留“密码 → 知识库”的引导；`/admin/settings` 使用独立页面，知识库、GitHub 凭据和密码按分区同时展示。左侧导航仅定位分区，不控制步骤；通过右上角“保存设置”统一提交，不需要先操作密码。

克隆、校验或保存配置失败时，原配置和已连接知识库保持不变；仅清理本次创建的未成功临时目录，不清理已有仓库。浏览器或网络中断时操作可能已经完成，请先在新标签页检查登录页和状态，不重复提交。

如果挂载目录消失或现有 Git 配置不再可用，程序仍提供原密码登录的恢复设置页，允许重新选择可用目录；不重新开放首次安装。仓库配置不完整时返回错误，不默默切换到本地保存。若配置文件本身损坏，则停止启动，请用 VPS 面板恢复配置备份。异常中断遗留的 `setup.lock` 可在确认无其他实例安装后，通过面板文件管理器移除。

备份整个数据卷，包含配置、Git 元数据、克隆笔记和旧目录；外部挂载目录需另行备份。不要同时启动多个可写实例共享同一知识库。当前 Git 分叉、未完成提交等复杂状态仍保持拒绝覆盖策略，可视化冲突解决不在此次安装向导范围内。

## 兼容旧命令

显式 `-vault` 继续使用旧启动模式，密码来自 `OBBLOG_ADMIN_PASSWORD`，默认允许编辑并自动识别 Git，不需要 `-write -git`。`-write=false`、`-git=false` 仍兼容显式禁用；该模式不提供系统设置。正常启动不带参数，在向导选择原目录即可。旧持久配置中的关闭编辑/Git 标记不再限制功能，无需修改配置文件。

## 验证边界

初始化/配置测试全部使用临时目录；克隆使用临时 bare remote，并注入测试替身将经过校验的 GitHub URL 映射到该本地远端，不访问真实 GitHub 内容或上传真实笔记。覆盖首次无安装码直接安装、密码摘要、权限、持久化、入口关闭、并发安装、后台设置鉴权、跨站拒绝、目录浏览、失败保留和恢复模式。浏览器验证使用独立临时实例，不接触真实知识库。Docker Compose 配置已检查；当前环境无法访问 Docker 守护进程，因此镜像构建和容器实跑尚未验证。
