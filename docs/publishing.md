# 发布到博客

## 操作

1. 在后台阅读一篇笔记，点击顶部“发布设置”。
2. 开启“发布到博客”，点击“查看文章”检查完整正文。
3. 旧文章可修改“发布时间（本地时间）”，再点“保存时间”。
4. 关闭开关撤下文章，再次开启保留原文章地址和发布时间。

笔记存在未保存草稿时，先完成保存并退出编辑，再发布。Git 模式发布新副本前检查本地与远端一致；远端有更新时先手动拉取。调整日期和取消发布不需要连接 Git 远端。

## 时间

- `publishedAt`：首次成功发布的时间，允许手动修改，不从文件 mtime 或 Git 提交日期推断。
- `updatedAt`：公开正文、标题或附件实际变化的时间。初次发布不额外显示“更新于”。
- 原始 YAML 属性和 Obsidian 注释不属于公开正文，单独修改它们不改变更新时间。
- 日期单独编辑不刷新正文；原笔记内容不会被改写。前台以北京时间显示日期，后台日期输入按浏览器本地时区转换并保存 UTC 时间。
- 不支持未来时间的定时发布。

## 更新

手动 Git 拉取/推送成功、网页保存成功后，更新已开启发布的副本。网页文件已经写入但推送失败时不更新公开内容；在 Git 管理中重试推送后更新。未启用 Git 时，网页保存更新副本；Obsidian 等外部程序修改目录后，在发布弹窗点击“更新已发布文章”。普通刷新、登录和公开页面请求不更新正文。

更新采用完整状态的原子替换。生成或持久保存失败时，继续提供上一份副本并在后台返回错误。Git/笔记保存已成功但副本更新失败，会明确返回部分成功警告；可重试“更新已发布文章”。首次发布失败不会产生可访问的新文章。

源文件删除后，下一次成功更新撤下对应文章和附件。Git 识别到的重命名保留 ID/发布时间；同步基点随发布记录保存，重试更新仍能读取重命名。Git 未识别的移动或非 Git 文件移动不猜测关联，需要重新发布。

## 内容与存储

`/` 是文章列表，`/posts/<ID>` 是完整文章，`/media/<ID>/<内容摘要.扩展名>` 是文章引用的附件。每篇文章使用随机固定 ID，不把知识库路径作为公开地址。

渲染使用复制的 Markdown 和当时解析的链接，不读取实时知识库。已发布目标的链接指向公开文章；目标撤下后不再生成公开链接。正文引用的附件复制到独立存储，更新前不会跟随原附件变化；文章撤下后旧附件地址也不可访问。YAML 只在后台展示，不用于文章属性或附件发布。

数据目录：

```text
data/publications/<知识库标识>/
  publications.json      发布开关、ID、时间、正文副本、链接映射与 Git 基点
  blobs/                 按内容摘要保存的附件副本
```

数据按知识库规范路径隔离。换库后不会把原发布设置应用到新库的同名笔记；换回原路径恢复原发布记录。备份/迁移需要同时保存配置、知识库和整个发布数据目录。迁移中改变知识库绝对路径时，标识会变化，需要迁移对应命名空间或重新发布。

当前不自动清理历史附件文件；取消发布属于撤下，不是永久清除备份。单实例使用，不提供多个进程共同修改同一发布目录的协调。

## 验证

```bash
go test -race ./...
go vet ./...
node --test tests/graph-model.test.mjs tests/editor-model.test.mjs
```

发布与同步测试只使用自动创建的临时笔记、临时 Git 仓库和本地 bare remote，不操作真实笔记或真实 GitHub 远端。
