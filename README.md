# OB Vault

一个用 Go 实现的 Obsidian 风格知识库后台和公开博客，支持 Web 安装向导、密码登录、目录阅读、Markdown 编辑、关系图谱、Git 同步和单篇发布。直接读取现有目录，不导入数据库，不依赖 Node.js 或前端构建工具。前端静态资源编译进 Go 二进制。

## Web 安装

VPS 推荐通过部署面板导入项目自带的 `compose.yaml`：镜像内置 Go 程序、Git 和 HTTPS 根证书，数据卷持久保存配置与克隆的笔记。首次部署后，安装、密码、仓库和读写选项都在浏览器完成，不需要用终端管理。详见 [VPS 安装说明](docs/installation.md)。

本地源码运行需要 **Go 1.25 或更新版本**；Git 模式另需系统已安装 Git。默认启动即可进入初始化：

```bash
go run .
```

打开 [初始化向导](http://127.0.0.1:8080/install)，直接设置管理员密码，再选择克隆 GitHub、连接服务器现有目录或新建空知识库。目录可直接浏览选择；GitHub 私有仓库在页面填写 Token。编辑、图谱和发布默认可用；Git 仓库自动接入同步，普通目录使用本地保存，没有功能启用复选框。

安装后进入 [后台登录](http://127.0.0.1:8080/admin/)。顶部“系统设置”可修改密码、目录和 Token；保存后立即生效并撤销旧会话。密码留空表示不更改，已保存 Token 不回显。根路径 `/` 为公开博客，按发布时间倒序展示已发布文章。

系统设置为独立的分区页面，知识库、GitHub 凭据和密码同时展示，可直接修改后统一保存；不再复用首次安装的分步向导。

构建独立程序：

```bash
go build -o bin/obblog .
./bin/obblog
```

默认监听 `127.0.0.1:8080`，配置目录为 `./data`，可通过 `-addr`、`-data` 调整启动基础设施。重启沿用配置，不重新安装，不依赖 `OBBLOG_ADMIN_PASSWORD`。所有知识库 API、附件和工作区资源均受会话保护，旧 `/api/...` 不提供私有内容。会话 12 小时有效，退出/重启后需重新登录；修改设置也会撤销全部旧会话。

HTTPS 和反向代理的 `X-Forwarded-Proto: https` 自动使用安全 Cookie，无需额外设置。管理员密码以 PBKDF2-SHA256 加盐摘要存储；Token 需用于 Git 认证，保存在权限为 `0600` 的私有配置中，不写入仓库 URL 或命令参数。配置目录不能置于笔记库内部。

### 兼容旧启动模式

显式传入 `-vault` 时仍使用旧的临时配置模式，需要 `OBBLOG_ADMIN_PASSWORD` 环境变量。该模式同样默认允许编辑并自动识别 Git 仓库，不再需要 `-write -git`；兼容参数 `-write=false`、`-git=false` 仅供旧模式显式禁用。该模式不显示 Web 系统设置。正常使用直接 `go run .` 或 `./bin/obblog`，仓库和密码在浏览器设置。

## 测试模式

```bash
go run . -test
# 或
./bin/obblog -test
```

每次从全新的安装向导开始，配置、密码、笔记、Git 仓库和公开副本仅放在独立临时目录，不读取或写入正常的 `data` 目录。选择服务器现有目录时复制笔记和附件，编辑不会修改原目录；克隆仓库后也转换为临时本地 Git 远端，提交、拉取和推送都在测试环境内进行，不向原仓库上传。

点击安装页、系统设置或后台顶部的“结束测试”，或用 Ctrl+C / SIGTERM 关闭程序，会等待操作结束、释放文件并删除整个测试目录。重新启动 `-test` 需重新安装。`-test -vault /path/to/vault` 仅预选导入来源，仍复制后操作；`-test` 下忽略 `-data`，不会清空正式数据。正常模式不自动删除数据。

清理范围是应用创建的测试数据，不包括浏览器历史、密码管理器、终端/部署面板日志；强制 `kill -9`、崩溃或断电无法执行退出清理。详细说明见 [测试模式](docs/test-mode.md)。

## 发布文章

打开笔记，点击后台顶部“发布设置”，开启“发布到博客”。首次发布生成固定地址 `/posts/<ID>`，文章页展示完整正文、附件和目录；首页显示标题、摘要和日期。发布不要求开启 Markdown 编辑权限。

发布时间默认为首次成功发布的时间，可在弹窗中修改为旧文章的实际日期，不支持定时发布。正文更新只改变更新时间，重复同步、重启和修改 YAML 属性不会重置时间。关闭开关后文章和对应公开附件返回 404；重新开启沿用原地址和发布时间。

公开副本在手动 Git 拉取/推送成功后更新，网页保存也会更新已发布文章；Git 保存推送失败时仍展示上一份公开内容，成功重试推送后再更新。未启用 Git 时，网页保存更新副本；外部修改本地笔记后，可点击“更新已发布文章”。这个按钮更新所有已发布文章，不发布其他笔记。普通目录刷新和前台访问不更新副本。

发布记录、正文及附件副本保存在 `data/publications/<知识库标识>/`，不修改 Markdown 或 YAML。备份时保留整个 `data` 目录。更换知识库使用不同的发布记录，避免同名文件被误发布。旧 `-vault` 模式同样使用 `-data` 保存发布记录。

已发布笔记之间的双链和 Markdown 链接转换为公开地址，未发布目标不生成可访问的文章链接。只复制正文实际引用的受支持附件，不发布 YAML 属性、Obsidian 注释或被链接笔记的正文。`![[笔记]]` 延续现有兼容行为，显示链接而不展开。源笔记删除并同步后自动撤下；Git 能识别的重命名保留文章 ID 和时间。非 Git 的文件移动，或 Git 无法识别的彻底改写，需要在新路径重新发布。

操作、时间规则与测试见 [发布说明](docs/publishing.md)。

## Git 同步

选择 Git 仓库后自动接入同步，在顶部“Git 管理”或左侧锁形按钮打开后台管理。点击“检查远端状态”只执行远端校验，不 fetch、不改变笔记。点击“手动拉取更新”才 fetch 并尝试快进；登录、打开页面和普通目录刷新均不自动拉取。安装时选择克隆仓库，会下载一次初始内容。现有仓库需要初始提交和 upstream；没有 `.git` 的普通目录使用本地保存。

进入编辑和保存时都检查实际远端：本地 HEAD 必须与远端一致，工作树必须干净；保存还检查打开笔记时的 HEAD 和正文 revision。保存后只暂存当前笔记、创建 `OB Vault <obvault@localhost>` 提交并尝试普通 push。被 Git 忽略或带特殊索引标记的笔记不能网页保存。未提交修改、分叉、未完成的 Git 操作或离线时停止，不自动 stash、合并、清理、重置或强推。

文件已写入但提交/推送失败时，返回已保存的 revision 和明确警告，不破坏性回滚。推送失败且工作树干净时可在后台“推送本地提交”重试；暂存/提交失败或分叉需 CLI 核对。手动推送会上传当前分支所有领先提交，请确认它们都是希望上传的内容。

Git 子进程有超时，不弹交互密码框；应用命令禁用本地 hooks、fsmonitor 和提交签名。服务内部协调读写，但不是跨进程锁，**避免同时用 Obsidian、CLI、Web 或多个实例操作同一工作树**。远端在检查后仍可能变化，普通 push 拒绝非快进并保留本地内容，不承诺分布式原子事务。说明与故障恢复见 [后台与 Git](docs/admin-git.md)。

## MVP 功能

- Obsidian 风格三栏布局：文件树、标签页阅读区、文章大纲；支持浅色/深色主题、移动端目录抽屉。
- 按文件名和路径搜索，`Ctrl+K` / `Cmd+K` 聚焦搜索，回车打开第一条结果，Esc 清空搜索。
- Markdown 标题、列表、表格、任务列表、引用、代码块、脚注和基础 Callout。
- `[[笔记]]`、`[[目录/笔记|别名]]`、`[[笔记#章节]]`、`[[#本页章节]]`，以及普通 Markdown 相对链接。
- `![[图片.png]]`、`![[图片.png|宽度]]` 和普通 Markdown 图片；PDF、音视频附件可点击打开，播放能力取决于浏览器。
- 原始 Markdown 只读查看，YAML frontmatter 折叠展示。
- 手动刷新目录，读取本地新增、修改和删除；支持直接链接、浏览器前进后退。
- 全库/局部关系图谱：力导向布局、入链与出链、1-3 层邻居、拖动节点、缩放平移、悬停高亮、点击节点阅读。
- 图谱支持标签、附件、未创建笔记和孤立节点筛选，方向箭头、按一级目录着色及基本力参数调整；提供可用键盘操作的节点选择器。
- 默认支持编辑/新建 Markdown、行号、双链补全、基础格式插入、实时预览和手动保存。保存带内容版本校验，切换或关闭未保存笔记时提示确认。

目录和笔记在请求时从文件系统读取，不缓存正文。普通刷新按钮重新获取文件树和当前笔记，**不会执行 Git 拉取**。

## 编辑笔记

点击笔记顶部的铅笔按钮，或在文件浏览器点击 `+` 新建，不需要额外启用编辑。编辑器按原始 Markdown 保存，不重新序列化 YAML；支持保留常见换行风格及 BOM。拖入、粘贴或选择图片后自动保存到知识库根目录、插入 `![[文件名]]` 并预览，同名自动编号，单张最大 20 MiB。Git 模式会提交推送图片，正文引用仍需保存。新文件的目标目录需已经存在，不包含目录创建、重命名或删除。

保存按钮或 `Ctrl+S` / `Cmd+S` 显式写入本地文件。输入 `[[` 可选择完整路径补全，Tab / Shift+Tab 缩进/取消缩进，Ctrl+B 插入加粗。宽屏提供编辑与预览分栏，窄屏通过“展开预览”切换。预览请求不会写入文件。

文件在打开后被其他设备同步或本地 Obsidian 修改时，旧版本保存返回 409，保留 Web 草稿，不提供强制覆盖按钮。可查看服务器正文或复制草稿，再退出编辑重新核对。保存失败和离线时不会显示“已保存”；切换笔记、图谱、刷新或退出编辑会提示处理未保存修改，关闭页面使用浏览器原生离开提醒。

未启用 Git 时保存仅写本地；启用后按上面的校验与提交推送流程执行。浏览器报告离线时暂停编辑与保存，Git 模式还在进入编辑/保存时校验远端连通性。未保存草稿只在页面内存，关闭或刷新后不能自动恢复。会话过期时返回 401，不主动跳离编辑器；可在管理面板从新标签页重新登录，再回原页面保存。

保存方式、限制和临时仓库验证记录见 [编辑功能说明](docs/editing.md)。

## 关系图谱

登录后点击左侧关系图谱图标，或访问 [后台图谱](http://127.0.0.1:8080/admin/?view=graph)。阅读笔记时，工具栏的图谱按钮打开当前笔记的局部关系图。

图谱从 Markdown 正文和 YAML 属性中的内部链接重建，不改写文件，也不读取 `.obsidian` 缓存。默认隐藏标签和附件，显示未创建笔记与孤立笔记。章节/块链接聚合到所属文件，重复链接记录次数，不生成自环；代码示例、原始 HTML、Obsidian `%% 注释 %%` 和外部网址不生成连线。

筛选框支持普通名称/路径子串、`path:目录`、`#标签` 和 `tag:标签`；不实现完整的 Obsidian 搜索语言。滚轮或 `+`/`-` 缩放，拖动空白处平移，拖动节点调整布局，`0` 适应视图。图谱设置中的节点选择器可定位节点并打开笔记。

“重新索引本地目录”仅刷新图谱，左侧目录刷新按钮同时刷新文件树。两者都不执行 Git 操作。当前按需全量索引，过滤和布局在浏览器执行；尚未实现大规模知识库的增量索引或布局 Worker。

研究依据、实现结构、兼容差异和真实库测试结果见 [关系图谱兼容说明](docs/graph-compatibility.md)。

## 兼容边界

这不是完整 Obsidian Web 复刻：编辑器是轻量 Markdown 源码编辑，不是 Obsidian Live Preview 或富文本编辑器。不提供 Canvas、Bases、插件运行环境、数学公式或 Mermaid 渲染。代码块作为代码显示，未进行语法高亮。

`![[笔记]]` 暂时显示为可点击链接，不展开正文，但参与关系索引；块引用 `#^block-id` 参与文件级关系索引，暂不支持阅读定位。Callout 只支持基础展示，不实现折叠语义。属性在阅读区原样展示，图谱解析 YAML 中的双链和标签。无效 YAML 会产生索引提示，正文仍索引。文件名与路径大小写敏感。

普通 Markdown 相对链接优先匹配源文件目录；显式带目录的 Wikilink 优先匹配仓库根路径。随后尝试唯一的路径后缀/文件名。同名且不能确定的链接会标记为未解析，图谱给出歧义提示，不随意连到某篇笔记，建议使用完整路径。

只列出 Markdown 和受支持附件（图片、PDF、常见音视频），其他文件忽略。隐藏文件、隐藏目录和符号链接不读取，包括 `.git` 和 `.obsidian`。单篇笔记上限为 8 MiB。原始 HTML 默认不执行；外部 HTTPS 图片可能向图片服务发出请求，所有外部资源均不属于本地附件访问控制范围。

## 项目结构

```text
main.go                    启动参数、HTTP 生命周期
internal/account/          加盐密码摘要与验证
internal/config/           持久配置、排他安装与原子替换
internal/vault/            目录扫描、文件读写、版本校验、链接解析
internal/markdown/         Goldmark 渲染及 Obsidian 双链扩展
internal/graph/            只读关系索引、节点和有向边聚合
internal/gitsync/          远端校验、快进拉取、提交推送
internal/publication/      发布记录、正文与附件副本、固定文章 ID
internal/web/              Web 安装/设置、后台鉴权、私有 API 与内嵌前端
Dockerfile, compose.yaml   VPS 部署面板构建与持久卷
demo-vault/                示例笔记和附件
docs/                     兼容研究和验证说明
tests/                    图谱和编辑器客户端模型测试
```

## 验证

```bash
go test -race ./...
go vet ./...
go build ./...
# 可选，需要 Node.js；仅运行客户端模型测试
node --test tests/*.test.mjs
# 可选，读取真实目录做图谱集成测试，不修改笔记
OBBLOG_TEST_VAULT="/absolute/path/to/vault" go test -race -v ./internal/graph
```

编辑测试全部使用 `t.TempDir()`，不会读取 `OBBLOG_TEST_VAULT` 或向真实仓库发送写请求。覆盖新增/保存、版本冲突、并发写入、只读模式、符号链接拒绝、跨站请求拒绝、源内容/权限保留、预览不落盘，以及草稿状态、换行、补全和多行缩进。

Git 测试使用临时 bare remote 和第二设备 clone，覆盖手动拉取、快进、旧仓库版本拒绝、提交推送、失败保留和重试、离线、脏工作树及分叉。鉴权测试覆盖匿名 API/附件隔离、旧入口关闭、错误密码、退出和跨站写入。未对真实 GitHub 仓库执行写入测试。

安装测试覆盖首次访问直接安装、跨站拒绝、并发安装、密码加盐、私有配置原子保存、重启恢复、设置修改撤销旧会话、克隆失败清理、已安装入口关闭和目录丢失后的认证恢复；均只使用临时目录与临时本地远端。

发布测试使用临时笔记与本地 Git 远端，覆盖完整正文、日期修改和保留、正文/附件副本、跨文章链接、取消发布、重启恢复、原目录不可用时读取副本、切换知识库隔离、存储失败保留旧状态，以及 Git 重命名、删除、网页保存和推送失败重试。

力布局库已内嵌到 `force.js`，运行和 Go 构建均不需要 npm 或 CDN。只有升级该依赖时才需要手动重新打包，具体命令见兼容说明。许可证保留在内嵌文件头和 `scripts/d3-license.txt`。
