# 在后台导入 Typecho 文章

在 OB Vault 登录后进入「设置与工具 → 发布设置 → Typecho 导入」。

1. 从旧 Typecho 数据库导出 **UTF-8 MySQL `.sql`**。可只导出 `*_contents`、`*_metas`、`*_relationships` 三张表及其数据；后两张表用来恢复旧标签和分类。支持常见 `INSERT ... VALUES`，自动识别表前缀，无需恢复数据库。单份最多 32 MiB、1000 篇符合公开和日期条件的候选文章；ZIP 请先在本地解压。
2. 选择文件，点「解析并预览」。核对标题、原发布时间、标签、分类、目标路径和跳过原因。这一步不写笔记、不提交 Git，也不发布。服务器只解析数据，不执行任何 SQL，也不保存上传的备份。
3. 点「导入并发布」确认。新文章写入当前知识库根目录的 `typecho/<旧 cid>.md`。YAML 包含 `title`、UTC `date`、`tags`（始终包含 `typecho`，再追加旧标签）、`categories`，另记录 `typecho_id` 和可选的 `typecho_slug` 供核对。公开页仍使用 OB Vault 的固定 `/posts/<ID>`；可在结果列表查看对应链接。

```yaml
---
title: 旧站文章
date: 2020-01-01T00:00:00Z
tags: [typecho, Markdown]
categories: [技术]
typecho_id: 42
---
```

只自动导入已到发布时间、公开、无密码且由 Typecho 标记为 Markdown 的文章。草稿、私密文章、独立页面和未标记的 HTML 不自动发布；用户、评论、设置和附件也不导入。正文中的外部链接保留原样，不会下载旧站附件，也不会把旧文章中的本地引用解析成当前知识库里的附件。旧站下线前请另行迁移图片并处理旧 URL 跳转。

同一备份可重复预览：已经按相同日期发布且内容一致的文章会跳过；有重名不同内容、目录链接、不同日期的记录或已撤下文章时，不覆盖、不重新公开。已改动的备份文件或导入目标需要先重新预览。

**Git 知识库**要求本地干净且与远端一致，导入会一次提交新 Markdown 并推送成功后才发布。若推送失败，本地笔记或提交可能已保留；先在「Git 管理」处理同步，再用同一备份重新预览和导入。对于已经写入但尚未公开、与备份内容完全一致的文件，重试时不重复写入。成功后可在归档页筛选 `#typecho`，按原发布日期查看迁移文章。
